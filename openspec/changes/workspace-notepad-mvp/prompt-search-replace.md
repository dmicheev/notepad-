## Контекст

Ты дорабатываешь notepad+ (Rust-редактор на gpui 0.2.2, crates/app +
crates/editor-core). Группы 1–5 готовы: Document на ropey + транзакции
+ History (undo/redo), мульти-курсор, фолды/закладки, подсветка
syntect (D12.1–12.3), CSV-колонки + порог 20 МБ по согласию (D12.4),
липкая шапка CSV (D12.5). Сейчас 230 тестов (116 app + 114
editor-core) — обязаны остаться зелёными.

Факты окружения, важные для задачи:

- `regex` 1 и `fancy-regex` 0.14 — УЖЕ зависимости editor-core
  (заложены с задачи 1.1); fancy-regex — ради lookaround (D2).
  `rayon`/`memmap2` в зависимостях НЕТ (см. «Ограничения»).
- Воркспейса ещё НЕТ (группа 7 не делана): «папка поиска» — выбор
  диалогом; дефолт — папка активной вкладки (если путь есть).
- Выбор папки: `App::prompt_for_paths(PathPromptOptions { files:
  false, directories: true, .. })` — поддерживается в gpui 0.2.2.
- Свободные клавиши: cmd-f, cmd-shift-f (занято: cmd-o/s/shift-s/w/
  z/shift-z/q/g/d/f2…). Биндинги — main.rs (`KeyBinding::new`),
  типы — actions.rs (`actions!`), обработчики — `on_action` на корне
  (паттерн D8.1, работают и при пустом списке вкладок).

## Задача

### A. 6.1 Панель поиска в файле (Cmd+F)

1. UI: панель поиска НАД редактором (не модальное окно, паттерн
   VS Code; layout — как у goto-оверлея, но постоянная пока открыта).
   ОТДЕЛЬНЫЙ FocusHandle (ловушка D9.2 — клавиши панели не должны
   доходить до `handle_key` редактора). Esc — закрыть, Enter —
   следующее, Shift+Enter — предыдущее.
2. Действие `FindInFile` (cmd-f) + биндинг; Cmd+F при непустом
   выделении в одной строке — предзаполняет запрос (рекомендация).
3. Движок — GPUI-free в editor-core (новый модуль `search.rs`):
   поиск по `Document` (ropey) с режимами текст/regex (fancy-regex;
   ошибка компиляции паттерна — сообщение в статус-бар, не паника),
   учёт регистра, целые слова. Совпадения — char-диапазоны.
4. Навигация: след/пред от ГЛАВНОЙ каретки, циклически; каретка в
   начало совпадения + `scroll_to_line`.
5. Подсветка ВСЕХ совпадений в рендере редактора (отдельный цвет от
   SELECTION — добавь в theme.rs) + счётчик «текущее/N» в панели.
   Инвалидация при правках — от строки правки (паттерн
   `invalidate_from`) либо ленивый пересчёт — реши по замеру, зафиксируй в D13.

### B. 6.2 Замена в файле

1. Поля «заменить на» + кнопки Replace (текущее/следующее) и Replace
   All в той же панели (раскрытие по toggle — на твоё усмотрение).
2. Regex-режим: подстановки групп `$1`/`$имя` (сценарий спеки
   `(\w+)@example\.com` → `<$1>`).
3. Правки — ТОЛЬКО транзакциями editor-core: добавь публичный метод
   модели по образцу `insert_text` (private `apply_tx` +
   `History::apply` уже дают undo/redo бесплатно). Замена — составная
   правка, НЕ группа последовательного ввода.
4. Replace по одному: последовательные применения корректно сдвигают
   последующие совпадения (пересчёт после каждой правки или offsets-
   компенсация — реши и зафиксируй).

### C. 6.3 Поиск по открытым вкладкам

1. Запуск — действие (рекомендация cmd-shift-f) с областью «вкладки».
2. Результаты — список (файл, № строки, фрагмент с подсветкой
   совпадения); рекомендация: секция SEARCH в левой панели по образцу
   BOOKMARKS/PERFORMANCE (project_panel.rs) — зафиксируй в D13.
3. Клик — активировать вкладку (`TabModel::activate`/`open_path`
   дедупликация не нужна — вкладки уже открыты) + каретка +
   `scroll_to_line`. Untitled-вкладки участвуют (контент в памяти,
   подпись «Untitled N»).
4. Совпадение в свёрнутом теле — переход к заголовку фолда
   (`visible_line_or_header` — уже в `scroll_to_line`); зафиксируй.

### D. 6.4 Поиск по файлам в папке

1. Папка — диалогом (`PathPromptOptions { directories: true }`),
   дефолт — папка активной вкладки; обход с подпапками.
2. Зависимости: РАЗРЕШЕНЫ `rayon` + `memmap2` (editor-core; D3 это
   планировал) — добавить в workspace.dependencies. Других новых НЕТ.
3. Скан: memmap + параллельно (rayon); фильтр по маске файлов
   (простой glob `*.rs`, `*.{ts,tsx}` — руками, без зависимостей);
   пропуск бинарных (NUL в первом чанке). НЕ-UTF-8 файлы: BOM/детект
   по образцу encoding.rs load-пути, поиск после декодирования —
   компромисс и его границы зафиксируй в D13.
4. Потоковые результаты: батчи через `cx.spawn` + канал, UI не
   блокируется; группировка по файлам, клик — `open_path` (дедуп
   вкладок) + позиция. Большой файл (200 МБ) не должен фризить кадры.
5. Тест производительности: воркспейс из 100 файлов < 2 с (release).

### E. 6.5 Замена по файлам

1. Подтверждение модальным `Window::prompt` (паттерн close-dirty;
   тесты — `cx.simulate_prompt_answer`).
2. Применение: затронутые файлы открываются вкладками (`open_path`),
   replace_all применяется В ПАМЯТЬ, `dirty = true`, НА ДИСК НЕ
   ПИСАТЬ (спека + решение design). Undo доступен в каждой вкладке.
3. Отчёт: «N файлов, M замен» — транзиентное сообщение статус-бара.
4. Повторный поиск по вкладкам/файлам видит ИЗМЕНЁННОЕ содержимое
   вкладок, не дисковое состояние (решение — зафиксируй в D13).

## Ловушки (проверено/подозрительно — читать обязательно)

- **Фокус панели**: отдельный FocusHandle (урок goto D9.2), иначе
  ввод уезжает в редактор; Esc/Enter панели не редактируют документ.
- **Подсветка совпадений в рендере**: фон — на div СВОЕГО сегмента
  (урок D9.1: фон на контейнере красит строку целиком); продумай
  приоритет совпадение/выделение/активная строка; ширины сегментов
  проверяются debug_bounds (gui_tests), 'static-литералы.
- **char vs byte**: Document — char-индексы (ropey), regex отдаёт
  байтовые offsets по &str — конверсия обязательна (паттерн
  `build_spans` в highlight.rs).
- **Rope НЕ материализовать в String** на больших файлах (память
  D11.4): поиск по чанкам с ПЕРЕКРЫТИЕМ — lookaround fancy-regex
  смотрит за границу чанка; размер оверлапа и остаточное ограничение
  зафиксируй в D13. Совпадение через границу чанков — тест.
- **Deferred-скролл** (D12.5): после `scroll_to_item` в GUI-тестах
  качай второй кадр (в живом окне его даёт следующее событие).
- **Клавиши в gpui::test**: keymap пуст (main() не выполняется) —
  хоткеи проверять через bind_app_keys + simulate_keystrokes,
  действия — dispatch_action (шапка gui_tests.rs).
- Каретка в col 0 НЕ создаёт пустой сегмент (урок CSV-теста).
- Пустой запрос / только пробелы / некорректный regex — no-op или
  сообщение, никогда не паника.
- Bench-режим (`NOTEPAD_BENCH=1`) неинтерактивен: новые диалоги не
  должны в нём спрашивать что-либо.

## Тесты (минимум)

- Юнит editor-core (search.rs): режимы текст/regex/регистр/целые
  слова; навигация след/пред циклически; replace по одному
  (последовательные сдвиги), replace all; `$1`-подстановка (сценарий
  спеки); regex-даты `\d{4}-\d{2}-\d{2}`; совпадение через границу
  чанка rope; поиск не-UTF-8 содержимого; undo после replace all.
- Модель app: применение к вкладкам, dirty, счётчики, сообщения.
- GUI: Cmd+F открывает панель (фокус — набор текста не правит
  документ), подсветка совпадений (debug_selector по ШИРИНАМ),
  Enter/Shift+Enter двигают каретку, счётчик, Esc закрывает;
  regex-сценарий с датами; замена + undo; поиск по вкладкам — клик
  по результату активирует вкладку/позицию; замена по файлам —
  `simulate_prompt_answer`, вкладки dirty, диск не тронут (сравнить
  байты), отчёт в статус-баре.
- Производительность: 100 файлов < 2 с — release-тест (по образцу
  ignored-бенчей или быстрый обычный на TempDir из 100 мелких файлов).
