# Промт: группа 5+ — CSV-подсветка и порог 20 МБ по согласию пользователя

> Статус: ВЫПОЛНЕНО (см. сводку в конце). Файл оставлен как
> воспроизводимое ТЗ и шаблон для повторного запуска/ревизии.
> Реализация: окт 2026, design.md D12.4, tasks 5.5–5.6.

## Контекст

Ты реализуешь правку группы 5 «Подсветка синтаксиса» notepad+
(Rust-редактор на gpui 0.2.2, crates/app + crates/editor-core).
Группа 5 (задачи 5.1–5.4, design.md D12.1–D12.3) уже готова: движок
`HighlightEngine` в editor-core (кэш спанов на строку, чекпоинты
стеков каждые 1024 строк, догон с бюджетом 2 мс/кадр, кап строки
8192), детект языка (extension → first-line), оверлей ручного выбора,
порог 20 МБ с автоОТКЛЮЧЕНИЕМ (устаревшее поведение — его правишь).

## Что сделать

### A. CSV/TSV: колонки чередуются цветами (задача 5.5)

Требование пользователя: «очень важно, чтобы колонки разделялись
цветом».

1. Грамматика-заглушка «CSV» (расширения csv, tsv) в
   editor-core/src/syntax.rs рядом с TOML — только для детекта/имени;
   sublime-грамматуры НЕ умеют индексные цвета — спаны строит движок.
2. editor-core/src/highlight.rs: `HighlightEngine` при синтаксисе
   «CSV» зовёт `csv_spans(line)` вместо syntect-парсера:
   - разделитель — большинством в строке (`,` vs `\t`, ничья →
     запятая), построчно, stateless (состояние проходит насквозь);
   - кавычки RFC-4180: разделитель внутри `"…"` не делит поле, `""` —
     экранированная кавычка;
   - классы `CLASS_COLUMN_A..D` (8..11) с ротацией по индексу колонки
     (пустые поля не красятся, но индекс считают); кап длины строки
     действует как для остальных;
   - char-координаты без терминатора.
3. app/theme.rs: 4 цвета колонок (Dark+: 0x9cdcfe / 0xce9178 /
   0xb5cea8 / 0xd7ba7d) в `syntax_color`.
4. Тесты (editor-core): чередование/ротация 4 цветов; кавычки с
   разделителем и `""`; TSV; пустые поля; кап; детект csv/tsv.
   GUI-тест app: `data.csv` → строка «a,b,c» рендерится сегментами
   полей+запятых (debug_bounds, паттерн gui_tests.rs; carетка в col 0
   НЕ создаёт пустой сегмент — режет первый текстовый).

### B. Порог 20 МБ → вопрос пользователю (задача 5.6, ПРАВКА СПЕКИ)

Требование пользователя: «при решении парсить или нет файл больше
20 мегабайт спрашивать пользователя; если согласен — раскрашивается
файл любого размера».

1. **Поправь спецификацию**
   openspec/changes/workspace-notepad-mvp/specs/syntax-highlighting/spec.md:
   - требование «Подсветка активна на больших файлах»: вместо
     «автоматически отключать, уведомив» — «спрашивать разрешение;
     при согласии подсветка работает для файла любого размера
     (прогрессивно, без блокировки ввода/прокрутки), при отказе —
     отключается с уведомлением»;
   - сценарий «Файл сверх порога» заменить на два: «отказ» и
     «согласие»;
   - в «Набор поддерживаемых языков» добавить сценарий «Открытие
     CSV-файла» (колонки чередуются цветами, кавычки RFC-4180, TSV).
2. Модель: `TabLanguage` — `over_threshold: bool` (файл > 20 МиБ) +
   `threshold_allowed: bool` (согласие); `disabled()` = over &&
   !allowed; `BufferTab::allow_highlight_despite_threshold()` включает
   и пере-детектит язык. АвтоОТКЛЮЧЕНИЕ без вопроса НЕ остаётся
   нигде (включая статус-бар и клик по языку).
3. Диалог (app): модальный `Window::prompt` «Enable / Keep off»
   (паттерн close-dirty в editor_actions.rs; тесты —
   `cx.simulate_prompt_answer("…")`). Точки: `open_paths` (после
   открытия), восстановление сессии и NOTEPAD_OPEN (очередь
   `pending_threshold_tabs` до создания окна, вопрос после),
   повторный шанс — клик по языку в статус-баре на вкладке без
   разрешения. Один диалог на все новые крупные файлы одного
   открытия. `NOTEPAD_BENCH=1` НЕ спрашивает (стенд неинтерактивен,
   цифры D11/D12.2 инвариантны).
4. Согласие → подсветка ЛЮБОГО размера: движок уже держит бюджет
   кадра (догон ≤2 мс/кадр, стеки окна → правки пересчитывают только
   окно независимо от размера файла); в сводку — прогрессивное время
   полного догонa для 200 МБ (ориентир ~23 тыс. строк/с).

  меняется; движок — GPUI-free editor-core, палитра — app/theme.rs.

  `cargo test --workspace && cargo build --workspace`, 0 предупреждений

  bench-режиме цифры не меняются).

  «отказ» (сообщение + редактирование); «согласие» (20 МБ+ красится,
  язык определён, ввод работает).
- design.md — новый подраздел D12.4 (решения: stateless-CSV, ротация 4
  цветов, семантика disabled(), очереди диалога, bench-гейт);
