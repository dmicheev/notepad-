# Design

## Context

MVP блокнота (change `workspace-notepad-mvp`) реализован: воркспейс с панелями split view (`Pane` ≤ 4 в `Workspace`), вкладки `TabModel`/`BufferTab` с `doc: Document` (ropey), подсветка syntect с кастомными движками (CSV/TSV), темы, i18n-крейт, меню/кеймап. Markdown сейчас подсвечивается встроенной грамматикой syntect — предпросмотра нет, любая зависимость Markdown отсутствует (Cargo.lock).

Новый режим — **живой предпросмотр Markdown**: панель справа от области редактора, рендерит активную Markdown-вкладку, обновляется при правках. Требования — в `specs/markdown-preview/spec.md` этого change.

## Goals / Non-Goals

**Goals:**
- Живой (без сохранения на диск) предпросмотр активной Markdown-вкладки: CommonMark + GFM-таблицы/зачёркивание/чек-листы.
- Рендер нативными gpui-элементами в активной теме; код-блоки — с подсветкой через существующий syntect-движок.
- Отзывчивость редактора независимо от размера просматриваемого файла (виртуализация блочного списка).
- Изолированный, тестируемый парсер: чистый крейт без GUI-зависимостей.

**Non-Goals:**
- Рендер изображений (MVP — плейсхолдер с alt-текстом; загрузка локальных/сетевых картинок — follow-up).
- Исполнение встраиваемого HTML/JS (CommonMark допускает inline HTML — показываем его как текст; безопасность и объём рендера вне MVP).
- WYSIWYG-редактирование в предпросмотре, синхронная прокрутка редактор↔предпросмотр, внутренние якоря-ссылки — кандидаты в follow-up.
- Экспорт в HTML/PDF.

## Decisions

### D1. Парсер: `pulldown-cmark`

Кандидаты (окт 2026):

| Крейт | Модель | Стандарт | Скорость/память | Вердикт |
|---|---|---|---|---|
| **pulldown-cmark** (0.13.x) | поток событий (pull) | CommonMark 0.31 + расширения: таблицы, зачёркивание, чек-листы | сотни МБ/с, O(1)-память на событие, нет аллокаций AST | **выбор** |
| comrak | полное AST в памяти | CommonMark + полный GFM | тяжелее (аллокации дерева), медленнее на больших файлах | избыточен: AST не нужен, рендерим за один проход |
| markdown-rs / иные | события/AST | CommonMark | сопоставимо, экосистема меньше | отклонено |

Потоковая модель идеально ложится на рендер: события напрямую конвертируются в блоки модели, полного дерева нет. Расширения включаются `Options::ENABLE_TABLES | ENABLE_STRIKETHROUGH | ENABLE_TASKLISTS` — покрывают GFM-часть спеки.

### D2. Архитектура: крейт `crates/markdown` (чистая модель) + рендер в `app`

По паттерну `i18n` (GUI-независимый крейт):

```
crates/markdown
  src/lib.rs      — модель документа
  src/parse.rs    — pulldown-cmark → модель
```

Модель — два перечисления без gpui-зависимостей:

```rust
pub enum Block {
    Heading { level: u8, inlines: Vec<Inline> },
    Paragraph(Vec<Inline>),
    CodeBlock { lang: Option<String>, code: String },
    List { ordered: bool, items: Vec<ListItem> },   // ListItem { inlines, children: Vec<Block>, checked: Option<bool> }
    Quote(Vec<Block>),
    Table { aligns: Vec<Align>, rows: Vec<Vec<Vec<Inline>>> },
    Rule,
    Html(String), // сырой HTML — рендерим моноширинным текстом (Non-Goal: исполнение)
}
pub enum Inline {
    Text(String, Marks),         // Marks { bold, italic, strike, code }
    Link { text: String, url: String },
    Image { alt: String, url: String }, // рендер: плейсхолдер
    SoftBreak, HardBreak,
}
```

Inline-стили схлопываются в `Marks` при парсинге (стек состояний emph/strong/strike) — рендер получает готовые флаги, а не дерево вложенных спанов. Вложенность блоков (список в цитате) — рекурсивно по модели; предохранитель глубины (например 64) от патологических файлов.

Рендер — новый модуль `app/src/markdown_preview.rs`: `Block` → gpui-элементы, `Inline` → строки `StyledText` с `HighlightStyle`-диапазонами. Юнит-тесты парсера (модель → assert) живут в `crates/markdown` без GUI.

### D3. Интеграция в Workspace: правая колонка, следование за активной вкладкой

Состояние в `Workspace`: `markdown_preview: Option<MarkdownPreview>` где

```rust
struct MarkdownPreview {
    scroll: gpui::ListState,          // прокрутка живёт между кадрами
    cached: Option<(TabKey, u64, Arc<Doc>)>, // memo: вкладка+ревизия → модель
}
```

- Раскладка: в `render_pane_area` справа от сетки панелей добавляется колонка (фиксированная доля ~50% ширины области редактора, при узком окне — минимум ~320 px). Split-панели и вкладки не перестраиваются — предпросмотр ортогонален им (соответствует спеке: «не изменяя раскладку split-панелей»).
- Источник — активная вкладка активной панели: `is_markdown(tab)` по расширению/выбранному языку (`md`, `markdown`, язык «Markdown» из `language.rs` — тот же критерий, что у подсветки). Не-Markdown вкладка → панель с заглушкой `preview.placeholder`.
- Закрытие просматриваемой вкладки/переключение — панель остаётся, источник пересчитывается тем же правилом (спека «Следование за активной вкладкой»).
- Тумблер: `ToggleMarkdownPreview` в `actions.rs`, `KeyAction`-вариант + `KeyDef { key: "cmd-shift-v" }` (на Windows gpui сам мапит cmd→ctrl, как у остальных биндингов), пункт меню View, ключи `menu.view.markdown_preview`, `status.preview_on/off`, `preview.placeholder`.

### D4. Живое обновление: ревизии документа + debounce

`Document` сегодня не имеет счётчика версий — добавляем `revision: u64`, инкремент в каждой транзакции (mutation-path один — `transaction.rs`), `pub fn revision()`. Полезен и дальше (инвалидация кэшей), дёшев.

Обновление предпросмотра:
- После правок редактор уже зовёт `cx.notify()` (существующие обработчики) — на кадре `markdown_preview` сравнивает `(tab_key, doc.revision())` с memo-ключом; при несовпадении запускает отложенный перерасчёт.
- Debounce: `cx.spawn` + `background_executor().timer(200 мс)`; правки подряд сбрасывают таймер (флаг «пересчёт назначен»). Спека требует видимость ≤ 300 мс после правки — 200 мс debounce укладывается.
- Парсинг: `doc.text()` → pulldown-cmark. До ~2 МБ это единицы мс — можно в UI-потоке; на всякий случай парсим в `background_executor().spawn`, модель возвращаем через канал и кэшируем в `cached`. Рендер всегда из кэша — кадр не парсит.

### D5. Рендер блоков: виртуализованный `gpui::list`

Блоки имеют переменную высоту → `uniform_list` (равные высоты, как в редакторе) не подходит. В gpui 0.2.2 есть `gpui::list` / `ListState` — виртуализованный список с переменными высотами (проверено по исходникам крейта). Предпросмотр = `list(state, render_block)`: на кадре рендерятся только видимые блоки — файл любого разумного размера не деградирует.

Отображение (активная тема из `theme.rs`):
- Заголовки: `text().size(базовый + (7−level)·шаг)` с `FontWeight::BOLD` — размеры различимы (спека).
- Абзацы/инлайны: `StyledText` + `with_highlights` (bold→weight, italic, strike→`strikethrough`, code→инлайновый фон-чип моноширинно, link→цвет ссылки + подчёркивание).
- Код-блоки: моноширинный шрифт редактора; при `lang` — построчные спаны через `editor-core::highlight::HighlightEngine` (тот же движок, что в редакторе; язык — `syntax::find_by_token`/по имени), без lang — монохром на фоне-чипе.
- Списки: рекурсивный `v_flex` с маркерами/номерами/чек-боксами (☐/☑ — глифами шрифта, без SVG-зависимостей).
- Таблицы: `h_flex` колонок с `flex-1`/`min_w` и разделительными линиями; выравнивание ячеек по `Align` из модели.
- Цитата: левая полоса + фон; `Rule` — `div().h(px(1))`.
- Ссылки: `InteractiveText`/`on_click` → `cx.open_url(&url)` (метод gpui 0.2.2, проверен) — только `http(s)://`, прочие схемы (в т.ч. `file:`, относительные) — стилизованы, но без действия.
- Изображения: чип «🖼 alt (url)» — плейсхолдер по спеке.

### D6. Темы

Цвета — из существующей `theme.rs` (палитра тёмная/светлая) + 3–4 новых токена (фон панели, рамка код-чипа, цвет ссылки, полоса цитаты). Переключение темы уже делает `cx.notify()` всего окна — предпросмотр перекрасится тем же кадром.

## Risks / Trade-offs

- **HTML-вставки**: CommonMark разрешает inline/block HTML — рендерим как текст (Non-Goal). Осознанное упрощение, зафиксировано в спеке («нераспознанные конструкции — как текст»).
- **Патологические файлы**: глубоко вложенные списки/цитаты → предохранитель глубины в парсере; очень широкие таблицы → горизонтальный скролл внутри блока (не ограничиваем макет).
- **`gpui::list` зрелость для стороннего кода**: элемент присутствует в 0.2.2; если обнаружатся артефакты измерения высот (блочный рендер с wrap-текстом) — fallback: разбивать длинные абзацы на под-элементы и/или собственный windowed-рендер по скроллу (задача 4.4 предусматривает проверку).
- **Отзывчивость на правках мегабайтных файлов**: полная перезапарска на каждый debounce-тик; для заметок (~КБ) — мгновенно, для МБ-файлов — десятки мс в фоне, UI не блокируется (D4). Инкрементальный парсинг не оправдан сложностью в MVP.
- **Совместимость клавиши**: `cmd-shift-v` свободна в текущем `keymap.rs` (проверено); конфликт с системными биндингами маловероятен.

## Migration Plan

Новое поведение за выключенным по умолчанию тумблером — миграция не требуется. `Document::revision()` — добавление, не ломает существующих API (внутреннее поле + аксессор).

## Open Questions

- Долю ширины предпросмотра (50% vs адаптивная) — решение в задаче 3.2 по итогам ручной проверки на узких окнах; спека фиксирует только «справа от редактора» и наличие панели.
